# Contributing to AIHACKBins

Thank you for helping build an open AI security research community.

## Ways to participate

- Suggest topics and missing research areas through issues.
- Correct technical inaccuracies and broken references.
- Improve documentation and accessibility.
- Propose reproducible techniques, safe test cases and AI-assisted security workflows.
- Independently reproduce or refute published findings.

## Contribution workflow

1. Search existing issues and pull requests for overlap.
2. Open an issue for major changes or new project-wide policies.
3. Fork the repository and create a focused branch.
4. Make the change with clear sources, attribution and supporting evidence.
5. Open a pull request using the template and respond to review.

## Minimum research standards

For technical entries in future knowledge-base repositories, document:

- Objective and affected component or workflow.
- Prerequisites, environment, versions and configuration.
- Reproduction steps and expected versus observed results.
- Limitations, false positives and failed attempts when relevant.
- Original references and contributor credit.
- Appropriate mitigation, validation or defensive context.

Mark untested claims **Unverified**. Do not suggest a result works universally across models or versions without evidence.

## Licensing and attribution

Contributions to this documentation repository are made under its [CC BY 4.0 licence](LICENSE), unless explicitly stated otherwise and agreed before merging. Only submit material you have the right to license. Link to upstream research rather than copying incompatible or unlicensed content.

## Publication and privacy

Use test data and authorised lab environments. Do not commit secrets, personal data, non-public customer material or sensitive unpublished vulnerability details. Use [SECURITY.md](SECURITY.md) for sensitive reports.

## Review

Maintainers may request revisions, evidence or improved attribution. Rejected or postponed changes should receive a brief reason. Respectful technical disagreement is welcome.
